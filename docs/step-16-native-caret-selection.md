# 步骤 16：原生光标、鼠标命中与选区

## 本步范围

画布新增点击定位、按住拖动跨行选择、反向选择、Shift+单击扩展、指针捕获、选区高亮和闪烁光标。交互坐标先用**实际呈现帧**的缩放与滚动逆变换为文档 DIP，再由布局中的字形簇、源码范围、双向级别和 Markdown 公式盒子映射为 UTF-16 位置。输入期间不修改文档；键盘编辑、撤销/剪贴板、TSF 输入法分别属于后续步骤。

选区的锚点与焦点保存原文版本、原文 UTF-16 偏移及软换行亲和方向，不保存窗口像素。重排或缩放提交后，用新布局重新求光标和选区矩形；旧版本位置不会错误地画在新版本上。普通正文和 Markdown 公式样张仍属于两份独立的只读源码；一个拖动手势只在按下时所处的源码内选择，暂不伪装成统一可编辑 Markdown 文档。公式（含 `$` / `$$` 定界符）是不可拆分的原文盒子。连续正文中的组合字符、代理对与 ZWJ 表情采用字素边界，生成的断词连字符不进入源码选区。

字形簇内若包含多个字素（例如连字），本步依据簇宽插值出合法的字素停靠点；它不伪称为字体提供的精确 ligature caret 度量。未来如需字形级精度，应在 shaping 阶段捕获 DirectWrite 的停靠数据。公式盒子内部逐字符定位则须先实现 Markdown 源码/呈现投影。

## 实现与验证

`TextInteractionMap` 是不依赖 WinUI 的几何索引，可由普通正文 `LayoutSnapshot` 和数学排版的实际 placement 构建。它提供命中、按原文偏移反查光标，以及对原文范围生成选区矩形；RTL 运行段的右侧边界对应源码起点。`EditorCanvas` 在画布上处理指针并只绘制交互覆盖层，不改变三个自定义窗口按钮的实现。旧重排尚未提交时，光标仍跟随上一帧正文和上一帧缩放比例。

纯测试覆盖点击、跨行/反向选区、软换行亲和方向、重排重投影、50%–300% 缩放与 DPI 逆变换、版本失配、RTL、字素簇、原子公式和空行。验收时还要在真实 WinUI 窗口核对点击、拖动、快速改变窗口宽度、缩放后选择保持、滚动、窗口三键与 Snap 悬停。
