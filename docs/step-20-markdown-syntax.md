# 步骤 20：Markdown 解析配置与语法测试集

本步在纯 `MDEditor.Core` 中加入 `MarkdownSyntaxParser`，不接管当前 WinUI 正文画布；步骤 21 才建立编辑投影和显示位置与原文位置的双向映射。右上角三个自定义窗口键、数学工作进程和现有输入法桥接均未改动。

## 解析配置

使用固定版本的 [Markdig 1.3.2](https://www.nuget.org/packages/Markdig/1.3.2)，以 CommonMark 基础语法为核心，显式启用约定的 GFM 子集：管道表格、任务列表、`~~双波浪~~` 删除线、裸 HTTP/HTTPS/WWW 链接。尖括号 URI/邮件链接属于 CommonMark 基础语法。没有启用 `UseAdvancedExtensions()`，因此脚注、下标、上标等不会无意改变普通文本的含义。

此处的“约定子集”不是宣称完整实现 [GFM 规范](https://github.github.com/gfm/)：单波浪删除线、裸电子邮件自动链接、HTML tagfilter 尚不在本配置内；脚注、数学扩展及结构化图片/公式编辑分别属于后续步骤。当前 `MarkdownMathDocument` 的最小公式扫描仍服务于已完成的正文公式链路，尚未由此语法树替换。

## 原文与节点契约

- 输入是不可变的 `SourceTextSnapshot`；解析结果保留同一个原文对象和版本。解析不会规范化 CRLF、Unicode 或 Markdown 标记。
- 根节点覆盖完整原文。子节点使用半开 UTF-16 `SourceRange`，按源码顺序嵌套；强调、链接、代码等节点的范围包含其定界符。未被节点覆盖的空白、表格分隔线和引用定义仍留在原文中，不能用节点拼接结果替代保存内容。
- Markdig 把引用定义附加为查找元数据，其附带范围不是定义在原文中的位置。本步不把该伪范围暴露为语法节点；引用链接本身有正确范围，原始定义文本完整保留。引用定义的可编辑投影留待步骤 21/22。
- 未闭合代码围栏的底层范围只包含起始围栏；本层将其扩展到所属容器末尾。表格行与空单元格的底层范围可能缺失；本层依据物理行和未转义的管道分隔符补足范围，管道符位于代码 span 中时不会被误当成列边界。
- 不完整的强调、链接、行内代码及围栏不会导致解析失败或改写原文。编辑缓冲提交新版本后重新解析，可识别补全后的语法。本步是全量解析；增量失效与局部更新属于步骤 28。

## 验收

`MarkdownSyntaxParserTests` 覆盖 CommonMark 块/行内语法、引用链接、表格、任务列表、删除线、裸链接、源码范围、CRLF/代理对/组合字符、不完整语法编辑、逐字符输入，以及空表格行和引用块内表格。运行：

```powershell
dotnet test --project tests/MDEditor.Core.Tests/MDEditor.Core.Tests.csproj -c Debug
```

步骤 20 的验收只证明纯解析层可用；它不表示标题、列表等已经在当前窗口实时富文本显示。当前应用仍是前几步的可编辑正文/公式样张。

本次验证：核心测试 Debug/Release 各 663 项通过（其中步骤 20 新增 19 项）；WinUI 应用 x64 Debug/Release 构建通过，应用输出包含 `Markdig.dll`。构建仍有一条现存的 `AppInfo.Current` CA1416 平台版本警告，与本步解析代码无关。本轮隔离构建目录在验证后清理，不留下重复的应用包。
