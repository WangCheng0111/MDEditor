# 步骤35：发布配置与整体回归

本轮范围：完善源码中的发布约束、依赖审计与整体回归，**不生成任何 MSIX/安装包**。不改变包身份、版本、证书、联网权限、文档或核心编辑功能。

## 已加入的保护

- 自包含 .NET、非单文件、不裁剪为项目默认值；构建发现不兼容设置或 Platform/RID 混用时立即报错。
- x64/x86/ARM64 共享发布配置不再被 Git 忽略，用户特有设置仍忽略。
- 数学程序集明确复制到发布输出，并与四个项目程序集一起排除过时 ReadyToRun 复用。
- 可重复运行的只读依赖审计；校验真实 PE 架构、JSON 依赖、清单、字体/资源/许可和可选的最新输出哈希。
- 数学与 starry-night 子进程使用包内 .NET/Node/WASM；专项验证不借用外部 Node/.NET 搜索路径、不下载资源。
- PDF 取色使用 Win2D 标准 WinRT out 参数接口，消除 C++ 结构体返回约定的架构差异。

## 如何重跑

用 Visual Studio MSBuild 分别 Build Debug/Release，显式 `GenerateAppxPackageOnBuild=false`；测试命令：

```powershell
dotnet test --project tests/MDEditor.Core.Tests/MDEditor.Core.Tests.csproj --configuration Debug --no-ansi --no-progress
dotnet test --project tests/MDEditor.Core.Tests/MDEditor.Core.Tests.csproj --configuration Release --no-ansi --no-progress
```

构建后执行 [依赖审计](Packaging.md)；发布配置负面测试与 12 组小型合成依赖损坏测试随核心测试运行，不改真实产物。架构互相不兼容时必须使用 `-StaticOnly` 并记录为未运行。

本机证据与未完成的目标机验收分开记录；构建通过不等于安装通过，不以开发包替代客户安装包验证。本轮生成的临时复制品/输出会清理，不删除原始文档、恢复记录或发布者已有的安装包。
