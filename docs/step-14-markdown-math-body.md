# 步骤 14：Markdown 正文中的行内与块级公式

## 范围

本步把 `$...$` 和 `$$...$$` 从独立诊断面板接入正文画布。公式布局由步骤 13 的持久 MathWorker 返回；Native 将其绑定为与文字共同参与重排的实测盒子，再由 Win2D 在同一个滚动、缩放、裁剪坐标系绘制。没有 WebView2，也没有把公式当作普通字符拉伸。

当前窗口使用只读 Markdown 验收样张。它和步骤 10 的正文样张各有独立的 `SourceTextSnapshot`，同处一张原生画布，但还不是可编辑的统一文档。步骤 14 不实现键盘编辑、TSF、完整 Markdown 块语法或完整 LaTeX 宏系统；这些不能仅凭样张显示正常就宣称完成。

## 数据与布局路径

1. `MarkdownMathDocument` 扫描不可变 UTF-16 源文：普通文本保留原范围，行内公式保留 `$` 分隔符范围和独立内容范围，单行及多行块级公式保留 `$$` 的范围。转义美元符、代码 span 与代码围栏不触发公式；不完整或空公式按原文保留。
2. 应用异步向既有 MathWorker 请求每个公式的真实布局，结果按源文起点绑定。请求未完成时先显示原有正文，完成后再提交含公式的新帧；不在启动/UI 绘制线程等待 Worker。
3. Native 对文字以 DirectWrite 实际塑形，数学对象以 Worker 返回的宽、高、深度作为不可拆盒子；`MarkdownMathFlow` 使用 Knuth–Plass 在段落层选择断行、按实测 glue 对齐非末行。行内公式与文字共享基线；块级公式独占一行并居中。禁则边界不产生可断的弹性间距。
4. 视口宽度变化重算断行，编辑缩放改变逻辑列宽；纯 DPI 光栅密度变化复用同一布局。不可行宽度明确返回 `NoFeasibleBreaks`，不缩放或切碎公式。源文范围、公式个数、行尾和中文禁则写入 Debug 报告。

## 验收

核心测试涵盖 `$`/`$$`、转义、代码围栏、空或未闭合公式、源码范围、公式不可拆盒、基线、非末行两端对齐、末行自然收尾、窄列失败，以及中文标点处不插入可断 glue。直接运行 `tests/MDEditor.Core.Tests/bin/Debug/net10.0/MDEditor.Core.Tests.exe --progress off` 检查全套测试。

打包后的窗口应有三处行内公式、一处块级公式；中文与英文段落在调整宽度/缩放时重新断行，绿色边界只要求非末行严格对齐；底部报告应显示 `Markdown 正文 4 个公式` 且无错误。检查 50%～300% 缩放、滚动、窗口调整、最小化恢复，以及三个自定义窗口键。开发诊断 JSON 的 `MarkdownMathReport` 应满足 `Passed = true`、`ForbiddenPunctuationSafe = true`、`SourceMapped = true`，常规可行宽度的 `InfeasibleBlocks = 0`。

步骤 13 的独立公式面板仍保留，方便比较 Worker 原始布局与正文中的重放；这不是第二个编辑窗格。
