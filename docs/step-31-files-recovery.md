# 步骤 31：打开、保存与崩溃恢复

## 文件工作流

- 工具栏提供“新建 / 打开 / 保存 / 另存为”，快捷键为 Ctrl+N / Ctrl+O / Ctrl+S / Ctrl+Shift+S。标题的 `*` 表示当前源码与最后保存的源码不同；撤销回保存内容会清除标记。字体预设、缩放、滚动不是 Markdown 源码，不参与脏状态。
- 初始排版样张作为未命名、未修改文档保留，首次保存时选择目标路径。新建是空白 Markdown 文档；打开文件不再插入只读样张数学页。打开后的普通段落沿用原生排版与当前字体预设。
- 打开支持本地 `.md`、`.markdown`、`.mdown`、`.mkd`、`.txt`，只接受严格 UTF-8（无 BOM/有 BOM）和带 BOM 的 UTF-16 LE/BE；不猜测本地代码页。保存保留检测到的编码/BOM、原文字符与已有换行，不自动规范化。新文档默认 UTF-8 无 BOM，普通 Enter 使用所在行的换行形式（否则继承邻近行，最后默认为 LF）。
- 保存先将全部字节写入同目录的临时文件并刷盘，然后原子替换目标；失败时旧文件不被截断，临时文件清理。覆盖已打开文件前检查字节指纹，若外部程序改动则拒绝覆盖，提示另存为或重开。保存进行期间继续输入时，只把实际写入磁盘的那份快照设为基线，后续输入仍保持未保存标记。
- 打开和新建时若当前文档已修改，可选保存、不保存或取消。关闭窗口也经同一保护，包括右上角自绘关闭键和系统关闭；保存失败、选择器取消或继续编辑时不关闭。
- 图片路径仅相对当前 Markdown 文件所在目录解析；`ms-appx` 演示资源仍相对安装包。当前仍不联网加载远程图片。

## 崩溃恢复

- 已提交的编辑在约 450 ms 无输入后生成检查点；窗口失焦时立即写入。检查点位于应用 LocalFolder 的 `active-document.recovery.json`，采用校验和及同目录原子替换，不修改用户的 Markdown 文件。
- 下次启动有检查点时提示恢复或丢弃；恢复后始终是未保存状态，明确保存才覆盖原文件。损坏的检查点不被静默删除/覆盖，自动恢复暂停并报错。
- 成功保存、撤销回已保存内容、丢弃修改或切换到新文档时清除检查点。崩溃发生在最近一次检查点完成之前的极短时间内，尚未记录到磁盘的输入无法保证恢复。

## 验证与边界

- x64 Release 构建通过；Core/排版 829 项测试通过。新增测试覆盖四种编码往返、混合换行、无效字节/控制字符拒绝、原子保存和外部冲突、恢复校验、保存途中继续输入及撤销回已保存状态。
- 当前原生文字排版仍不接受 Tab、软连字符和若干控制字符；包含它们的文件会在打开前明确拒绝，文件不被改写。单文件上限 32 MiB；这不是多文档/多窗口实现，也没有远程文件同步。
- UI 验收建议：在 VS x64 Release F5 启动；新建并输入中英文/公式→保存→关闭重开；修改后看标题 `*`、Ctrl+Z 回保存内容；尝试关闭时分别取消/保存/不保存；用 CRLF/BOM 测试文件比较保存前后字节；编辑后等待 1 秒强制终止进程再重启，确认恢复提示与未保存标记。
