# 步骤 24：代码块与基础语法高亮

Core 从同一份 Markdown 语法树识别围栏代码、缩进代码、语言信息和未闭合围栏。围栏及引用容器前缀仅在显示投影中折叠；光标进入代码块时显示原始标记，源码、UTF-16 偏移、换行和撤销历史均不改写。整块选择可包含隐藏的围栏；代码中的 Markdown 行内标记及数学公式不作为正文格式处理。

Native 使用 Cascadia Code 原生字形、自然行宽、独立圆角背景和语言标签。代码行不做两端对齐、英文断词或自动连字；基础词法着色覆盖 C 系语言、Python、JSON、Shell/PowerShell 和 SQL 的关键词、字符串、数字、注释、类型及运算符。未知语言仍以纯文本显示；着色只改变画笔，不重新塑形或改动布局快照。着色扫描限制为每次 16,384 个 UTF-16 单元，超过预算的后续代码保持原色，避免巨型代码块长期占用输入线程。

本步不加入代码专用工具栏、完整语言服务器或水平滚动。超出视口的极长物理代码行保留自然宽度，当前视口会裁剪右侧；后续需补水平滚动或独立的代码软换行策略。基础着色不是完整编译器级语义高亮。

自动验收包括闭合/未闭合围栏、引用内围栏、缩进代码、演示样张的相邻代码块、语言标记、原文映射、进入/退出折叠、行首缩进时的着色、语法色范围、未知语言及扫描预算。Debug/Release 各 748 项 Core 测试通过，WinUI x64 Debug/Release 构建通过；构建尚有既存的 `AppInfo.Current` CA1416 提示。人工验收确认代码样张、输入法/连续删除、撤销/重做、缩放与窗口键正常。曾由旧 `AppX` 暂存 DLL 和空围栏几何自检触发的启动错误已修复，最终 Release x64 重新部署并正常启动。本轮隔离构建输出已删除。
