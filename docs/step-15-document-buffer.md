# 步骤 15：文档文本缓冲与编辑事务

## 范围

本步只建立 `MDEditor.Core` 中可独立运行的文本编辑核心。它尚未连接画布、光标、键盘、Markdown 编辑投影或中文输入法；这些分别在后续步骤实现。窗口与右上角三个自定义金刚键没有改动。

## 数据契约

`DocumentTextBuffer` 使用 UTF-16 偏移与既有的半开 `SourceRange`，内部为 piece table：未修改的文本片段与新插入片段只保留引用及范围，不在每次按键时拼接整篇文档。`CaptureSnapshot()` 在需要解析或布局时才生成不可变 `SourceTextSnapshot`，同一版本重复获取返回同一个对象；一次真实提交使版本单调加一并使快照、行索引失效。空事务、空插入和原样替换均不增加版本。

`BeginTransaction()` 记录基础版本和长度。事务内可调用 `Insert`、`Delete`、`Replace`，所有范围都指向提交前的原文；提交时按原文起点排序，拒绝重叠范围和同位置的多个插入。整批操作验证并构造完成后才替换当前 piece table，失败不产生部分修改。若已有其他事务先提交，则抛出带预期/实际版本的 `DocumentVersionConflictException`，防止旧编辑覆盖新文档。`DocumentEditResult` 返回旧/新版本、长度和每个变化的旧/新范围及原文/新文，为后续撤销和源码映射提供信息，但本步不实现撤销栈。

缓冲区不转换 Unicode 正规化形式，也不统一换行。插入文本必须是有效 UTF-16；编辑端点不得切开代理对或 `CRLF`。`DocumentLineMap` 根据不可变快照记录每一行的正文范围、精确换行范围及 `LF`、`CRLF`、单独 `CR` 或无换行，末尾换行后仍有一个空行。旧快照和旧行索引在之后的提交中保持不变。组合字符与 ZWJ 序列按原文保留，但“光标不得进入字形簇内部”的交互规则属于步骤 16/17；本步不把合法的 UTF-16 编辑范围误称为视觉光标位置。

## 验收

步骤 15 新增 14 项测试，覆盖插入、删除、替换、跨行、多点事务、旧/新坐标映射、原子失败、过期版本、空操作、版本溢出、代理对、组合字符、混合换行、跨 piece 的 `CRLF`，以及 700 次单点与 300 轮双点随机编辑对字符串基准的逐次比较。全量 `MDEditor.Core.Tests` 在 Debug 和 Release 下运行；该测试项目不加载 WinUI。由于本步没有 UI 接线，不能把纯核心测试当成光标、键盘或输入法验收。
