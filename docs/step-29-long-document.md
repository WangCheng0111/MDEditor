# 步骤 29：长文档视口、缓存与调度

本步骤保持原有 Markdown 编辑、原生字形/数学排版与窗口交互语义不变，处理长文档下不必要的全篇遍历和旧结果发布。

## 实现

- `ViewportIntervalIndex<T>` 为原生行、章节、表格、公式、代码面板和行内装饰建立不可变纵向区间索引。滚动绘制只枚举与视口相交的候选对象；索引在后台布局构建时生成，画布线程不再每帧扫描全部行。
- 已完成布局缓存同时受 32 帧和估算的 96 MiB 保留成本约束。最近使用的宽度优先保留；旧帧退出缓存时释放其原生资源。缓存预算不等同于进程工作集上限。
- 超过 512 个物理行的文档不在 UI 线程尝试同步缓存求解；新的编辑/尺寸请求取消过期后台构建。后台结果仍经版本、宽度和缩放门禁，只有当前结果或明确允许的中间结果可发布。
- 视口锚点使用原始 Markdown 源码坐标（而非折叠后显示坐标）重定位。源码改动时按共同前后缀重映射偏移，避免长文档后段编辑越界。
- 长文构建的段落样式、标题、块标记、公式与代码禁区改为索引查询；行内装饰只查当前行重叠样式。特别修正数学扫描逐字符遍历全篇代码区间的二次复杂度。

## 固定样张与结果

Release x64、当前开发机的单次测量：1024 个独立段落、61,354 个 UTF-16 单元，每段含加粗、代码、行内公式及中文。首次完整解析约 36 ms，编辑投影约 58 ms，富文本投影约 36 ms；中段插入 1 字符后的增量解析约 4 ms、投影约 13 ms；1024 次视口候选查询合计约 10 ms。数字是开发机样本，不是所有硬件的保证上限。测试记录在 `LongDocumentPerformanceTests`，不以机器耗时作脆弱断言。

真实 WinUI 开发包用 300 段混合样张复测：长文末段插入与撤销、大跨度滚动、最大化和 110% 缩放正常，状态栏无“排版失败”；滚动条固定值 20000 时最大化前后保留同一参考段落。长文测试时观察到主进程约 301 MiB 工作集（包含 WinUI、字体、画布和布局），不是纯布局缓存占用。

全量 Core/排版回归为 820 项通过。发布安装包需要重新按 Release x64 打包；本步骤仅同步并验收当前开发包暂存的 DLL。

## 边界

本步骤把绘制限制为视口，并将全篇快照合成放在后台；没有把 Knuth–Plass 正文求解改造成“只布局可见段落”的虚拟文档。首次打开非常大的文档仍需构建全篇一致的行断、引用和数学依赖。后续若要求百万字级文档的固定内存上限，需要另行设计分片布局及全局高度估计，不能由本步骤的绘制索引代替。
