# 步骤 25：Markdown 数学识别与公式源码编辑

Core 对同一份原始 Markdown 快照识别 `$…$`、`\(…\)`、`$$…$$` 和 `\[…\]`。后两种是独占物理行的展示公式，也接受起止分隔符各占一行的多行写法。识别结果保留 UTF-16 源码、内容和分隔符范围；转义、不完整分隔符、行内代码、缩进代码及闭合或未闭合围栏中的符号维持字面文本。公式内部的 `*`、`_` 等 TeX 字符不再被 Markdown 投影隐藏或着色。

Native 从原始源码范围映射到显示投影，用 MathWorker 的真实公式盒子参与混排。单击已排版公式会展开 TeX 源码供原位修改；光标离开后重新折叠。多行展示公式在布局就绪后合并成一个居中的公式段，源码和原有换行不变。复制、粘贴和邻接删除覆盖四种分隔符；单独的展示公式粘入句中时自动补齐所需的换行。

MathWorker 的公式错误包含公式内 UTF-16 偏移；编辑器映射到原文行列，状态栏提示并用红线标识原文。错误公式不被替换或丢弃，同段中其他合法公式仍能排版。无效或不完整公式的文本始终可以继续修改。

自动验收覆盖四种形式、多行及 CRLF、代码隔离、转义/不完整分隔符、源码映射、源码展开、剪贴板换行和错误位置协议。Debug/Release 各 757 项测试通过，WinUI x64 Debug/Release 构建通过；数学服务原生字形、结构化错误与位置回归通过。人工验收确认四种公式、点击编辑与折叠、错误行列及红线、缩放、删除和三个窗口键正常。构建仍有既存的 `AppInfo.Current` CA1416 提示；本步生成的临时数学服务报告已删除。
