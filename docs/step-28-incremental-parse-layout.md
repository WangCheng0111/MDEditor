# 步骤 28：增量解析、依赖失效与局部排版复用

## 实现

- `MarkdownIncrementalParser` 接收前一版不可变语法树和新源码快照。对于被空行隔离、仍保持普通段落形态的编辑，只重新交给 Markdig 解析该段；前缀节点保持身份，后缀节点及其子节点按 UTF-16 长度差平移。源码、换行、Unicode 和定界符不被改写。
- 若编辑改变围栏、列表、表格、标题等块结构，或可能触及跨段的引用定义/引用用法，则退回全量解析。增量结果必须与全量解析的节点类型和源码范围一致；宁可扩大失效范围也不能保留旧结构。
- 光标进出同一源码版本的 Markdown 结构只重建显示投影，复用语法树，不再重复调用 Markdig。新源码版本按上述增量路径或保守全量路径取得语法树。脚注、公式标签和图片引用索引仍在新版本中统一重算，因此定义变更可更新远处的显示结果。
- 原生排版会话在段落数变化时按未改前缀/后缀重新对齐，复用文字的字形塑形与候选行测量；即使中间跨过表格/公式对象，也不丢失后续文字会话。每个文字会话保存最多 8 个宽度/策略对应的断行结果，源码偏移平移且候选不变时继续复用。被编辑的段落及依赖变化的视觉对象重建。

## 边界

本步的“局部布局更新”指昂贵的字形塑形、候选测量与 Knuth–Plass 求解可按未改段落复用。每次提交仍会合成新的全局布局快照、重新计算纵向坐标并构造显示映射；超长文档的视口分片绘制、布局缓存和后台调度属于步骤 29。含跨段依赖的编辑故意全量解析，不以错误的局部结果冒充完成。

## 验证

- Debug/Release 核心测试各 812 项通过；增量测试覆盖中英文/Emoji/CRLF、连续版本重映射、未闭合格式补全、围栏/列表/表格/引用定义回退、远处图片目标更新，以及多种插入边界与全量 Markdig 树等价。
- x64 Release 的 Core、Native、WinUI 应用可编译。真实开发包启动后，正文可显示；输入字符、新增段落后仍保持排版，状态栏无“排版失败”。
- 建议人工进一步检查：在长段落中连续输入与回删；编辑围栏开闭、列表标记、链接定义及脚注定义后观察后续块/远处引用；跨段增删换行、撤销重做、缩放和调整窗口。步骤 29 再以固定长文测量延迟、滚动及内存。
