# 步骤 26：Markdown 表格与单元格编辑

Core 通过 Markdig 的 GFM 表格语法节点识别表头、分隔行、数据行、对齐方式与单元格，所有范围保留原始 Markdown 的 UTF-16 坐标。结构解析区分真正的列分隔符、转义的 `\|` 与行内代码中的竖线；显示投影折叠表格分隔符和对齐行，但不改写原文。对单个转义竖线复制、剪切或删除时会连同其转义反斜杠一起处理，避免留下孤立字符。

Native 以真实字形测量各列，同行共享列宽，绘制表头、行列边界与左/中/右对齐的单元格。单元格和边距均参与原生光标命中与选区映射；缩放与窗口宽度变化沿用现有的文档坐标和缓存重排链路，不引入 WebView。表格内容仍是同一份 Markdown 源码，字重、斜体与行内代码字体作用于单元格文本。

编辑器在表格内使用 Tab / Shift+Tab 切换单元格，末格 Tab 插入新行首格，Enter 或工具栏插入新行时保留当前列；工具栏还提供删行和增删列。结构修改作为一次可撤销的源码事务，不改变表格外文字，保留原有换行符。单元格内键入或粘贴竖线自动转义，行内代码内部的竖线保持原样；中文输入法的预编辑与上屏继续使用现有桥接。工具栏操作先清空输入桥的暂存片段，避免新格输入沿用旧格锚点。

自动验收覆盖 CRLF、无首尾竖线、空单元格、转义与行内代码、跨单元格 Tab、行列增删、源码/显示映射、三种列对齐、单元格边界与空白命中。Debug/Release x64 各 780 项测试通过，WinUI 构建通过。首次验收发现的空单元格命中点负长度异常已修复并加入回归测试；后续还修正了新增行的同列落点、单元格左右空白的点击归属与尾随空格位置、表格内代码圆角底的绘制顺序。对编辑页面左右留白的点击现在不会吸附到表格行首尾；在表格行高度内、列网格之外的点击也不会回退到通用文本命中。一次性诊断代码与日志已移除。
