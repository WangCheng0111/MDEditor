# 步骤 21：编辑投影与双向源码映射

本步把步骤 20 的 Markdown 语法树转换为不可变的编辑投影，不改写原文。显示文本只隐藏已经能够明确定位的语法标记；WinUI 正文目前仍使用原有的原文排版路径。标题、强调、链接等在应用中的实时样式切换属于步骤 22，列表/引用、代码块、表格、图片分别属于后续步骤。本步没有修改标题栏、三个自定义窗口键、数学工作进程和输入法桥接。

## 投影范围

`MarkdownEditProjection` 目前支持折叠/展开 ATX 与 Setext 标题标记、强调/加粗/双波浪删除线定界符、行内代码反引号、链接标签外的标记与目标地址，以及尖括号自动链接的尖括号。未闭合语法保留原样；空链接不被投影成不可见对象。公式 `$...$`、图片、引用、列表、任务标记、围栏、表格结构和 HTML 仍保留原文，待对应结构编辑步骤引入适当的可见对象或样式后再隐藏。

投影保留原 `SourceTextSnapshot` 对象和版本，另建同版本的 `Display` 快照；两者的文本长度可能不同。所有偏移仍是半开 UTF-16 坐标。隐藏定界符两侧会压到同一个显示位置，所以 `ToSourceOffset` 明确要求 `BeforeHidden` / `AfterHidden` 亲和方向，不能猜一个唯一原文位置。进入语法节点时可从同一原文构建展开投影，显示其标记；退出后重建折叠投影，不修改原文。不同展开状态即使源版本相同也必须视为不同布局，几何桥接用显示快照的对象身份拒绝旧布局。

例如原文 `a **b** c` 投影为 `a b c`。显示位置 `b` 前可以对应原文起始 `**` 前，也可以对应 `b` 前；方向决定插入点属于格式内还是格式外。逐字移动只跨显示字素，不停在隐藏标记内部。Backspace/Delete 选择相邻的完整显示字素；如果删掉一个格式节点的全部可见内容，删除范围会连同其隐藏标记一起扩大，避免残留空的 `****` 或 `[](url)`。部分删除只改可见内容，保留周围标记。选区既可映射可见内容的原文范围，也可在剪切/删除时按完整节点扩大；反向选区的方向由原有 `TextSelection` 保留。

`MarkdownProjectionInteractionMap` 将投影文本的 `TextInteractionMap` 命中、光标矩形、水平移动和选区矩形重新绑定到原文光标。它要求几何图使用该投影的同一个 `Display` 快照，而不只比较版本号，因此不会把上一个展开状态的几何误用到新状态。

## 验收与边界

新增 27 项测试覆盖：定界符折叠/展开、嵌套格式、链接与代码 span、标题换行、双侧位置映射、跨语法选区、完整/部分删除后重新解析、CRLF 与 Unicode 字素、不完整语法组合、旧几何拒绝、点击与视觉箭头回映射。Debug 和 Release 全量测试各 690/690 通过；WinUI x64 Debug 和 Release 构建通过。运行：

```powershell
dotnet test --project tests/MDEditor.Core.Tests/MDEditor.Core.Tests.csproj -c Debug
```

本步是以后接入画布的纯数据及几何契约，尚不宣称当前窗口已像 Typora 一样实时隐藏语法、显示富文本。显示样式、指针进入/离开时重新排版、格式命令和实际编辑器接线从步骤 22 开始；长文增量解析留待步骤 28。
